# 微信公众号推送（告警补充配置）

> 与 `部署说明.md` 配合使用。企业微信是主力通道，公众号作为**第二条独立通道**（微信生态内不同入口，一个被折叠另一个还能看到）。

---

## 1. 先确认你的公众号类型

| 账号类型 | 能否主动推送 | 具体限制 |
|---|---|---|
| **订阅号（个人 / 未认证企业）** | ❌ **不行** | 没有模板消息与订阅通知权限，只能被动回复用户消息 |
| **服务号（未认证）** | ❌ 不行 | 模板消息能力需认证后才有 |
| **服务号（已认证，300 元/年）** | ⚠️ 有限 | 只能发「订阅通知」，用户必须**先点订阅**；一次性订阅只能推一条，长期订阅仅开放给政务/医疗/交通等特定行业 |
| **接口测试号**（微信官方开发者工具） | ✅ **可以** | 免费、免认证，能给自己发模板消息。**告警场景首选** |

**结论**：

- 你的号如果是订阅号 → 这条路走不通，用第 3 节的企业微信 + 邮件即可；
- 如果是已认证服务号 → 走第 4 节，但要接受「每次告警前要先订阅」的现实限制；
- **最实际的方案是接口测试号**（第 2 节），专门给"自己收告警"用，和你的正式公众号互不冲突。

---

## 2. 路线 A：接口测试号（推荐，10 分钟搞定）

### 2.1 申请

浏览器打开：

```
https://mp.weixin.qq.com/debug/cgi-bin/sandbox?t=sandbox/login
```

用你的微信扫码登录，页面会直接给你：

- **appID** / **appsecret**
- **测试号二维码**（用你自己的微信扫它关注，关注后才有 openid）
- **用户列表**（扫码后能看到你的 openid，`o` 开头那串）
- **模板消息接口 → 新增测试模板**

### 2.2 建一个模板

点「新增测试模板」，填：

| 字段 | 内容 |
|---|---|
| 模板标题 | `NAS 网络告警` |
| 模板内容 | 见下方 |

模板内容（**字段名必须和脚本配置一致**）：

```
告警类型：{{first.DATA}}
详细内容：{{keyword1.DATA}}
发生时间：{{keyword2.DATA}}
备注：{{remark.DATA}}
```

保存后会得到一个 **模板 ID**（一串字母数字）。

### 2.3 部署脚本

```bash
cp wx-push.sh /usr/local/bin/wx-push.sh
chmod 700 /usr/local/bin/wx-push.sh

cp wxpush.conf.example /etc/wxpush.conf
chmod 600 /etc/wxpush.conf
vi /etc/wxpush.conf      # 填 appID / appsecret / openid / 模板ID
```

配置要点：

```bash
WX_MODE="template"
WX_APPID="测试号的 appID"
WX_SECRET="测试号的 appsecret"
WX_OPENID="用户列表里你那条 openid"
WX_TEMPLATE_ID="刚创建模板得到的 ID"
WX_FIELD_TITLE="first"      # 与模板里的 {{first.DATA}} 对应
WX_FIELD_BODY="keyword1"
WX_FIELD_TIME="keyword2"
WX_FIELD_REMARK="remark"
```

### 2.4 测试

```bash
/usr/local/bin/wx-push.sh "推送测试" "如果你收到这条，说明公众号通道已打通。"
echo "退出码: $?"
```

手机上会收到「服务通知」里的模板消息。**注意**：模板消息会折叠在微信的「服务通知」会话里，不是普通聊天消息。

### 2.5 接进看门狗

`netwatch.sh` 已经内置了调用逻辑，只需要 `/etc/netwatch.conf` 里这一行指向脚本（默认就是）：

```bash
WX_PUSH_CMD="/usr/local/bin/wx-push.sh"
```

然后：

```bash
/usr/local/bin/netwatch.sh test
```

三个通道（企业微信 / 邮件 / 公众号）任一成功即算送达，脚本会全部尝试。

## 3. 关于订阅号（如果你的号是这类）

个人主体订阅号**没有**模板消息和订阅通知的接口权限，这不是配置问题，是平台策略，绕不过去。可行的替代：

| 方案 | 说明 |
|---|---|
| 企业微信机器人 | 见 `部署说明.md` 第 1 节，免费无限制，**推荐** |
| 接口测试号 | 本节第 2 部分，和你的订阅号并存，专门收告警 |
| PushPlus / Server 酱 | 第三方，扫码绑定微信，免费额度够告警用 |
| 微信「服务号 + 长期订阅」 | 只有特定行业类目能申请，个人号无解 |

> 订阅号能做的是「被动回复」：你在公众号里发个关键词，它回你当前状态。这属于"查询"而不是"告警"，适合做补充功能（比如发「状态」回复当前网络检测结果），需要自建服务器接收微信回调，工作量远大于收益。

## 4. 路线 B：已认证服务号的订阅通知

如果你确实是认证服务号，并且模板类目支持长期订阅：

### 4.1 创建订阅通知模板

微信公众平台 → **订阅通知 → 我的模板 → 选用模板**（从模板库选一个"设备告警/状态通知"类的），得到模板 ID 和字段名（如 `thing1` / `time2` / `thing3`）。

### 4.2 用户订阅

订阅通知必须用户主动订阅：

- **一次性订阅**：用户点一次，你只能推一条；
- **长期订阅**：仅政务、医疗、交通、教育、金融等特定行业开放，个人自用基本申请不到。

> 所以服务号路线对"无人值守告警"并不友好：你得每次断网前都订阅一次——显然不现实。

### 4.3 如果仍然要用

```bash
WX_MODE="subscribe"
WX_TEMPLATE_ID="你的订阅模板 ID"
WX_FIELD_TITLE="thing1"     # 按实际模板字段改
WX_FIELD_BODY="thing2"
WX_FIELD_TIME="time3"
```

接口会变成 `/cgi-bin/message/subscribe/bizsend`，脚本已支持。

## 5. 常见错误码

| errcode | 含义 | 处理 |
|---|---|---|
| `40001` / `42001` | access_token 无效或过期 | 脚本会自动清缓存重取；若反复出现检查 AppSecret |
| `40003` | openid 无效 | 确认 openid 是**关注了这个公众号**的那个用户 |
| `43004` | 用户未关注公众号 | 让该微信先扫码关注（测试号页面有二维码） |
| `45009` | 接口调用次数超限 | 测试号有每日上限，告警场景不会触发；别拿它做高频推送 |
| `47003` | 模板参数不合法 | 字段名与模板不一致，或值超长（模板字段通常限 20 字） |
| `40037` | 模板 ID 无效 | 检查模板 ID，或模板已被删除 |

排查时直接看脚本输出（它会把 errcode 和响应原文打到 stderr）：

```bash
/usr/local/bin/wx-push.sh "调试" "手动测试"
```

## 6. 几个实际使用中的坑

1. **消息在「服务通知」里**，不在聊天列表。如果开了微信的「服务通知」免打扰，可能看不到 → 检查 微信 → 我 → 设置 → 消息通知 → 服务通知 是否开启。
2. **有延迟**：测试号模板消息通常几秒内到达，但网络波动时可能延迟数分钟。**别把它当实时告警的唯一通道**。
3. **字段长度限制**：模板字段一般限 20 个字符，正文太长会被截断或报 47003。脚本里已经把告警正文压缩成短句，如果自定义模板要留意。
4. **access_token 全局唯一**：同一个 appID 的所有调用共享一个 token，脚本做了文件缓存（`/var/lib/wxpush/token`，提前 300 秒刷新），避免频繁刷新导致旧 token 失效。
5. **测试号不能给别人用**：它只对扫码关注的人生效，且不能上线运营。这正是它适合"自己收告警"的原因。

## 7. 三通道对比（配置完后的效果）

| 通道 | 到达速度 | 需要什么 | 限制 |
|---|---|---|---|
| 企业微信群机器人 | 秒级 | 企业微信 App | 需要装企业微信，记得加后台白名单 |
| 邮件（QQ SMTP） | 几秒~1 分钟 | 授权码 | 可能进垃圾箱，建议发给自己 |
| 公众号模板消息 | 几秒~几分钟 | 测试号或认证服务号 | 折在「服务通知」，字段限长 |

看门狗会**同时尝试三个通道**，任一成功即认为送达（避免单通道故障导致漏报）。告警内容一致，你可以只在手机上留一个最顺手的。
